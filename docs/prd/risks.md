## 已确认的产品决策

> 以下决策已与需求方确认，作为设计基线（2026-06-24）。

| 编号 | 决策 | 落地说明 |
| --- | --- | --- |
| D1 | **计费定价采用纯按量（pay-as-you-go）** | 不做套餐包/订阅制；统一按 Token / 按次的用量计费（见 [计费规则](./billing.md)）。阶梯价等如有需要，后续迭代再评估。 |
| D2 | **组织成员额度按「金额」控制** | `member_quotas.quota_limit/quota_used` 以最小货币单位（金额）计量，而非 token 数量；消费时累计金额。按模型分别限额暂不纳入，后续迭代评估。 |
| D3 | **失败请求不计费** | 仅「成功 / 部分成功（流式已产出内容）」计费；上游报错、鉴权失败、无可用渠道等失败请求不产生费用，预扣冻结额度全额释放。 |

> 赠送余额相关决策（2026-08-16 补充，**待需求方确认**）。

| 编号 | 决策 | 落地说明 |
| --- | --- | --- |
| D4 | **赠送余额与充值余额分池记账，赠送优先消耗** | 钱包内拆 `gift_balance` / `balance` 两池 + `gift_grants` 批次账本；扣减优先级 赠送 → 现金 → 授信。不采用「只打备注标记」方案，否则无法支持有效期、撤回与退款上限计算。 |
| D5 | **赠送余额有有效期，默认 30 天，且不可退款 / 不可提现 / 不可转移** | 到期由定时任务作废并写 `gift_expire` 流水；支持「永久有效」但需显式确认。退款与提现上限只看现金池。 |
| D6 | **用量与账单必须区分资金来源** | `usage_logs` 拆 `gift_charge_amount` / `cash_charge_amount`；**平台真实收入口径改为 `cash_charge_amount`**，赠金消耗作为营销费用单列，不再计入毛利。 |
| D7 | **个人钱包与组织钱包均支持赠送** | 表结构按 `wallet_id` 设计，天然兼容两类主体。组织成员额度 `quota_used` 按总消费累计，不区分资金来源。 |

## 主要风险

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 高并发下余额超扣 | 高 | 行级锁/原子扣减 + 预扣实扣 + 幂等 |
| 上游协议频繁变更 | 中 | 适配器隔离 + 自动化回归测试 |
| 上游成本与定价倒挂 | 中 | 成本字段核算 + 利润看板告警 |
| 流式中断导致计费偏差 | 中 | 按已产出用量结算 + 对账兜底 |
| 凭证泄露 | 高 | 加密存储 + 脱敏 + 审计 + 轮换 |
| 估算用量误差 | 中 | 保守预扣 + 实扣校正 + 标记估算 |
| 赠金被批量注册薅羊毛 | 高 | 赠送不做自动发放（仅后台人工 / 受控活动）+ 单笔与日累计上限 + 赠金转化率看板 + 实名/邮箱验证前置 |
| 后台误操作 / 内部舞弊赠送 | 高 | 仅超管+财务角色 + 幂等键防重复 + 全量审计日志 + 超限告警 + 可撤回未消耗部分 |
| 收入口径失真（赠金算成收入） | 中 | `usage_logs` 拆分资金来源 + 报表收入口径改为现金部分 + 每日对账校验（D6） |
| 赠金过期与进行中冻结冲突 | 低 | 过期任务遇 `gift_held > 0` 跳过该钱包下轮重试 + hold 对账任务兜底 |
